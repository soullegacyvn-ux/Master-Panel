MASTER PANEL 1.2.0 — BASED ON 1.1.1

INSTALL AND OPEN
Exit the previous Master Panel from its tray menu. Extract this ZIP to a
fixed folder and run Master-Panel-v1.2.0.exe as Administrator.
Press the Win 5 Keyboard/Mouse <-> Gamepad Swap button to show/hide the
panel. Controller navigation should become available without touching
or clicking the panel. Release any held buttons/sticks, then use the pad.
Ctrl + Alt + Space and the tray menu remain alternate ways to open it.

Settings now has only the Open with Windows checkbox for startup.
Saved fan mode restoration and the device keyboard button are built-in.
Enabled startup schedules automatically repair their EXE path after moves.
Local controller profiles remain; OpenWinControls sharing and all Lossless
Scaling controls/background integration have been removed from this build.
Your separate LS installation and previous settings files are not deleted.

BRIGHTNESS
Both sliders retain your newest choice until Windows reports completion.
Manual app launches keep current Windows brightness; saved startup restore
runs only for Open with Windows. Failures show beneath the sliders.

CONTROLLER MAPPING
Select a button/output, then Done to stage the change.
Temporary -> Apply temporary mappings changes RAM for the current session.
Permanent -> Flash mappings writes controller storage after confirmation,
backup, firmware validation and RAM readback. A matching RAM mapping must
still be committed if Permanent is requested.
The status shows the current transaction stage. A missing reply times out.
Slow synchronous HID calls request Windows cancellation; if a driver ignores
it, the transaction stays busy and its outcome remains unconfirmed. Never
classify a blocked/unknown operation as a successful flash. Keep backups.
If a commit journal is present, automatic restoration remains paused.
Successful flash acknowledgement/readback still requires reboot testing.

AUDIO
FxSound exit status 1 no longer prevents waiting for a new valid status reply.
A fresh supported status file and matching fields still verify every action.
Repeated Refresh clicks are coalesced. FxSound remains a separate install
that must support its --status and EQ command options.

RTSS
In-game overlay -> Handheld offers six metrics in three columns, smaller
labels and larger values. Existing presets/position/enable preference remain.
RTSS continues reporting the game's own FPS; no frame-generation estimate
is fabricated. Handheld uses the existing RTSS text/font interface.

TDP AND BATTERY
Performance displays battery percentage, net charging power, current derived
from battery voltage, and estimated time to full or remaining battery time.
Charge time uses the current rate; charging taper may extend it. Unknown
voltage/rate/capacity or relative units hide unsupported physical values.
No extra battery polling, external process or power-management mode is added.

VALIDATION LIMITS
Portable regression tests, UI handler mocks, race checks and Windows vet
passed. All Windows test packages compile and the x64 GUI EXE/icon/admin
manifest are inspected. Windows binaries, controller/brightness/focus,
FxSound/RTSS rendering and GPD hardware have not been run on this Mac.
Windows and device-specific behavior still needs testing on the Win 5.
PawnIO, WebView2 and separately installed RTSS/FxSound are used as before.
